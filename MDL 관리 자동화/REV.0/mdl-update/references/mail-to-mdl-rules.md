# 메일 판정 및 MDL 입력 규칙

## 공통 근거

- 현재 메일 제목과 인용문을 제외한 새 본문
- 발신자·수신자와 프로젝트명
- 실제 첨부파일명과 문서 내부의 DOC. NO./Revision
- 대상 MDL에 존재하는 정확한 DOC. NO.
- 회신 문서에 명시된 검토기관과 Approval/Status Code

DOC. NO.가 없거나 둘 이상과 충돌하면 입력하지 않는다.

## 제출

- 제출일은 실제 제출 메일의 발송일 또는 본문에 명시된 제출일을 사용한다.
- 하나의 Issue에서 제출일은 검토기관과 무관하게 공통이다.
- Revision은 해당 제출 첨부파일에 표시된 값을 사용한다.
- `REPLY SHEET` 문구만으로 접수로 판단하지 않는다. `승인도서 및 REPLY SHEET 제출`은 제출 근거이다.

## 접수

- 접수일은 해당 검토기관에서 회신한 현재 메일의 날짜를 사용한다.
- 검토기관 A와 검토기관 B 등 검토기관을 구분하여 각각의 접수일·STATUS 열에 입력한다.
- `검토의견 송부`, `에 대한 회신입니다`, 검토의견서, COMMENT/CRS와 동일 DOC. NO.는 강한 접수 근거이다.

## STATUS

- 허용 코드는 프로젝트 프로필의 `allowedStatuses`를 따른다.
- 예시 프로젝트 현재 프로필의 허용값은 `A`, `AC`, `NA`, `I`, `IC`이다.
- 메일 제목의 일반적인 승인 표현만으로 코드를 추정하지 않는다.
- 접수일은 있으나 STATUS 근거가 없으면 STATUS는 빈칸으로 둔다.

## Revision과 Issue

- Issue는 MDL의 제출 이력 차수이다. 같은 DOC. NO.의 제출 순서를 기존 이력과 대조한다.
- Revision 표기는 첨부 원문을 그대로 사용한다. 숫자와 문자를 임의 변환하지 않는다.
- 같은 Revision의 재송부인지 새 Issue인지 불명확하면 입력하지 않는다.

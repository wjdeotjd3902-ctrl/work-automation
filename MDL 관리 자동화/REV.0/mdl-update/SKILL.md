# MDL 최신화

## 역할

도서관리 메일의 검증된 정보를 기존 MDL 양식에 맞게 입력하여 갱신된 작업본과 검증 결과를 생성한다.

## 입력값

| 항목 | 내용 | 필수 여부 |
|---|---|---|
| 프로젝트명 | 대상 프로젝트 | 필수 |
| MDL 파일 | 현재 사용하는 기존 작업본 | 필수 |
| 메일 위치 | 도서관리 메일 폴더 | 필수 |
| 조회 기간 | 근거를 확인할 기간 | 필수 |
| 프로젝트 프로필 | 시트·문서번호·차수·검토기관별 열 매핑 | 선택, 없으면 분석하여 생성 |

## 수행 방법

### 1. 근거와 양식 확인

`outlook-document-mail-routing`으로 정리된 폴더에서 현재 제목, 새 본문, 실제 첨부 및 문서 내부의 DOC. NO.와 Revision을 확인한다.

`scripts/discover_mdl_profile.py`로 현재 MDL을 읽기 전용 분석한다. 프로필이 없으면 시트·문서번호 열·데이터 행·차수별 열을 검토하여 `references/profiles/<project>.json`에 저장한다. 기존 프로필도 매번 대조하고 `headerSignature`, 필수 머리글, 병합 영역이 다르면 쓰기를 중단한다.

### 2. 변경 계획 및 사전 검증

[메일 판정 및 입력 규칙](references/mail-to-mdl-rules.md)에 따라 변경 계획 JSON을 생성한다. 근거 없는 필드는 제외한다.

`scripts/apply_mdl_updates.ps1`을 `-Apply` 없이 실행하여 셀 주소·기존 값·새 값·충돌을 확인한다. 기존 값과 다르면 기본 중단하며 검토된 항목에 `replaceExisting: true`가 있는 경우만 교체한다.

### 3. 적용 및 재검증

해당 실행이 승인되면 같은 계획에 `-Apply`를 추가하여 자동 백업 후 기존 작업본을 갱신한다. 새 MDL 양식을 만들지 않는다.

저장 후 다시 열어 변경값과 레이아웃을 검증한다. 병합·선·행높이·열너비가 바뀌면 백업을 복원하고 실패로 보고한다.

## 출력값

| 항목 | 형식 | 내용 |
|---|---|---|
| 프로젝트 프로필 | JSON | 문서번호·차수·검토기관별 입력 위치 |
| 변경 계획 | JSON | 문서번호, 차수, 필드, 값, 근거, 교체 허용 여부 |
| 갱신 작업본 및 백업 | Excel | 승인된 값이 반영된 기존 MDL과 변경 전 백업 |
| 검증 결과 | 로그 및 요약 | 반영값, 충돌·실패, 재열기와 레이아웃 확인 결과 |

## 주의사항

- 허용 필드는 Revision, 제출일, 검토기관별 접수일·STATUS다. STATUS는 회신 문서에 명시된 코드만 사용한다.
- 날짜 근거가 없으면 빈칸을 유지하고 `미접수`, `누락`, `0`을 대신 입력하지 않는다.
- 값만 입력하며 병합·테두리·색상·글꼴·행높이·열너비·수식은 유지한다.
- Flag·Outlook 범주·메일 위치는 변경하지 않는다.
- 긴 첨부 경로 때문에 증거를 확인할 수 없을 때만 `outlook-shortpath-attachments`를 사용한다.

## 예시

### 입력값

기존 MDL 작업본, 프로젝트 프로필 및 검증된 회신 근거를 [계획 예시](references/update-plan-example.json) 형식으로 준비한다.

```powershell
pwsh -File scripts/apply_mdl_updates.ps1 -PlanPath '<계획 JSON 경로>' -LogPath '<검증 로그 경로>'
```

### 출력값

```text
Dry Run: 셀 주소 / 기존 값 / 새 값 / 충돌
승인 후 적용: 기존 작업본 갱신 / 자동 백업
재검증: 변경값 / 레이아웃 / 성공·실패
```

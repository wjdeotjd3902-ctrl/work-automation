# 도서메일 분류·정리

## 역할

프로젝트 메일을 도서 판정 기준에 따라 처리하여 분류·이동 결과를 생성한다.

## 입력값

| 항목 | 내용 | 필수 여부 |
|---|---|---|
| 프로젝트명 | 기존 폴더와 대응할 대상 이름 | 필수 |
| 조회 기간 | 미지정 시 전체 기간 | 선택 |

## 수행 방법

### 1. 폴더 확인 및 수집

실제 Outlook 폴더 트리에서 프로젝트를 찾고 해당 메일함을 사용한다. 후보가 여러 개면 실제 경로를 제시하여 확인한다. 접근 실패를 폴더 없음으로 간주하지 않는다.

프로젝트 폴더가 없으면 기존 `받은 편지함\PJT\진행중` 아래에, 해당 구조도 없으면 기본 메일함의 받은 편지함 아래에 만든다. 대상은 프로젝트 바로 아래의 기존 도서관리 폴더를 재사용하며, 없으면 `도서관리` 하나만 만든다.

`scripts/scan_outlook_document_mail.ps1`로 프로젝트 폴더에 직접 들어 있는 메일만 읽기 전용 수집한다. 하위 폴더와 이미 정리된 메일은 재처리하지 않는다. 전체 기간은 `-StartDate '1601-01-01' -EndDate '9999-12-30'`으로 전달한다. 빈 폴더는 0건으로 보고하고 종료한다.

### 2. 식별 및 사전 검증

[판정 규칙](references/classification-rules.md)에 따라 현재 제목, 새 본문, 송수신 방향, 실제 첨부파일, DOC. NO. 및 Revision을 대조한다. 확실한 접수·제출만 계획 JSON에 기록하고 확인 필요·무관 메일은 제외한다.

`scripts/apply_outlook_document_routing.ps1`을 `-Apply` 없이 실행하여 건수·중복·누락·현재 폴더를 검증한다. 확정 후보가 없으면 적용 스크립트를 실행하지 않는다.

### 3. 적용 및 결과 확인

프로젝트 정리 요청은 폴더 생성·범주 지정·이동을 포함한다. 검증 오류를 해결한 후 같은 계획에 `-Apply`를 추가한다. 확정 메일에는 접수·제출 중 하나만 남기고 다른 범주는 유지한다.

적용 로그의 실제 EntryID로 메일을 다시 읽어 대상 폴더와 범주를 확인하고 성공·실패·확인 필요 건수 및 경로를 보고한다.

## 출력값

| 항목 | 형식 | 내용 |
|---|---|---|
| 변경 계획 | JSON | 메일함, 원본·대상 경로, 실제 메일 ID, 판정, 문서번호, 근거 |
| 처리 결과 | 로그 및 요약 | 접수·제출 건수, 이동 성공·실패, 확인 필요 건수, 실제 경로 |

## 주의사항

- 읽기 전용 또는 Dry Run 요청에서는 폴더 생성과 메일 변경을 하지 않는다. 스킬 편집 요청도 실제 정리를 실행하지 않는다.
- 메일·기존 폴더 삭제, Flag 및 Excel 변경은 하지 않는다.
- 제목·과거 인용문만으로 분류하지 않으며, 제출물의 REPLY SHEET는 접수 증거가 아니다.
- 첨부 내부 확인에 긴 경로가 장애가 될 때 `outlook-shortpath-attachments`를 사용한다.
- 같은 원인으로 세 번 실패하면 중단하고 의심되는 전제를 명시한다.

## 예시

### 입력값

예시 프로젝트 프로젝트의 전체 기간 도서 메일을 분류하고 정리한다.

### 출력값

아래는 실제 처리 결과가 아닌 계획 형식 예시다.

```json
{
  "mailbox": "확인한 메일함",
  "sourceFolder": "확인한 프로젝트 상대 경로",
  "targetFolder": "확인한 도서관리 상대 경로",
  "items": [{
    "entryId": "실제 EntryID",
    "storeId": "실제 StoreID",
    "classification": "접수",
    "docNo": "확인한 DOC. NO.",
    "reason": "현재 본문과 검토의견 첨부의 문서번호 일치"
  }]
}
```

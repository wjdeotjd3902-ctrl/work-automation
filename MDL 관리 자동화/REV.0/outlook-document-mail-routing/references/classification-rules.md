# 도서메일 판정 규칙

## 공통 필수 근거

다음 근거를 함께 사용한다.

- 현재 메일의 제목과 인용문을 제외한 새 본문
- 발신자와 수신자 방향
- 실제 첨부파일명과 파일 종류
- 문서번호(DOC. NO.)와 Revision
- 가능하면 대상 MDL에 존재하는 문서번호

MDL이 제공된 경우 해당 프로젝트의 문서번호와 대조한다. MDL이 없다는 이유로 입력을 요구하거나 작업을 중단하지 않는다. 프로젝트·설비 범위가 맞지 않거나 도서 여부가 불확실하면 `확인 필요`로 남긴다.

## 접수

발주처·검토처에서 돌아온 회신, 검토의견, 승인 결과 또는 COMMENT/CRS를 받은 메일이다.

강한 근거 예시는 `검토의견 송부`, `에 대한 회신입니다`, `검토의견서`, Approval Code, COMMENT/CRS 파일과 동일한 DOC. NO.이다.

## 제출

당사에서 승인도서나 수정도서를 제출·송부·업로드한 메일이다.

강한 근거 예시는 새 본문의 `제출드립니다`, `첨부하여 제출`, `송부드립니다`, `업로드 완료`와 DOC. NO./Revision이 있는 실제 제출 첨부파일이다.

`승인도서 및 REPLY SHEET 제출의 건`에서 REPLY SHEET는 접수 증거가 아니라 제출물의 일부이다.

## 제외 또는 확인 필요

- 전달·일정·문의·독촉·단순 확인 메일
- 해당 프로젝트의 도서가 아닌 자료. 문서 종류명만으로 일괄 제외하지 않는다.
- 인용된 과거 본문에만 `회신`, `제출`, `검토`가 있는 메일
- 제목과 본문은 제출처럼 보이지만 첨부파일이나 DOC. NO.가 맞지 않는 메일
- 하나의 현재 메일에서 접수와 제출 근거가 충돌하는 경우
